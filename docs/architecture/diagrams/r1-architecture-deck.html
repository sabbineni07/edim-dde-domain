edim-dde-ai 1.0.0 YAML schema, LangGraph builder, registries, llm_chain, invoke_agent, LangSmith hooks SQL, Foundry credentials, HTTP, product prompts

Security

Identity, secrets & PII

Keep current auth model · Key Vault SDK · expandable FinTech PII patterns

Identity (unchanged model)

  • SQL (Apps): user OAuth via forwarded token
  • SQL (local): az login / DefaultAzureCredential
  • Foundry (local): DefaultAzureCredential
  • Foundry (PROD): SP from Key Vault → env

Role matrix — docs only in Phase 0

  • invoke — call agent APIs
  • operate — LangSmith / support
  • administer — register agents, rotate secrets
  • approve_tools — future HITL / MCP gates

Documented now; API does not yet enforce role claims.

Key Vault bootstrap

  • SDK loads secrets at API startup
  • Maps vault names → env vars
  • Does not overwrite already-set env (local .env wins)

PII guardrails (expandable)

  • SSN · credit card · account # · member id
  • Current agents: telemetry only (no expected PII)
  • Pattern registry designed for easy extension

Observability

LangSmith in the architecture

Cloud projects per env for SDBX/DEV/PROD · self-hosted Docker needs Enterprise license

Recommended for local testing

LangSmith Cloud (SaaS)

  • Create projects: edim-dde-sdbx / -dev / -prod
  • Set LANGCHAIN_TRACING_V2=true + API key + project
  • EDIM tags: agent_id, env, request_id
  • Works from laptop without Docker of LangSmith itself

Optional · Enterprise only

Self-hosted LangSmith (Docker)

  • Official Docker Compose exists for dev/test
  • Requires LangSmith Enterprise license key
  • Not open-source; not for free local spin-up
  • See platform/langsmith-setup.md § Local / Docker

Correlation fields

  • request_id — from X-Request-Id or generated UUID
  • EDIM_ENV — sdbx | dev | prod
  • agent_id — cluster_tuning / spark_rca / plugins
