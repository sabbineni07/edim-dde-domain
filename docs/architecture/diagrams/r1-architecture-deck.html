Package view

Responsibility boundaries

ai = reusable agent runtime  ·  domain = Databricks + product semantics  ·  api = thin HTTP host  ·  Dependency: api → domain → ai

Package Version Owns Does not own
edim-dde-ai 1.0.0 YAML → LangGraph runtime, registries, llm_chain, retrieval, stores, observability, scoring hooks Databricks SQL, Foundry credentials, HTTP, product prompts
edim-dde-domain 1.0.0 Databricks SQL / UC, Apps auth, Foundry adapter, Key Vault, workspace pick, cluster_tuning · spark_rca HTTP middleware, generic graph runtime
edim-dde-api 1.0.0 CORS, Apps token + RequestId middleware, lifespan bootstrap, /api/v1 DTOs, safe boundary logging Agent business logic, SQL collectors

Design rule

  • Framework stays Databricks-unaware. Product SQL lives in domain YAML + one domain.sql.query node.

Security stance

  • YAML cannot import arbitrary Python; node/router ids must be pre-registered

Security

Identity, secrets & PII

Identities U / A / B · Key Vault SDK · expandable FinTech PII patterns

Identities U / A / B

  • U (SQL Apps): user OAuth + scope sql
  • U (SQL local): az login / DefaultAzureCredential
  • A: App SP opens Key Vault (DATABRICKS_CLIENT_*)
  • B: Foundry SP → EDIM_FOUNDRY_* (never AZURE_CLIENT_*)

Role matrix — docs only for now

  • invoke — call agent APIs
  • operate — LangSmith / support
  • administer — register agents, rotate secrets
  • approve_tools — future HITL / MCP gates

Documented now; API does not yet enforce role claims.

Key Vault bootstrap

  • SDK loads secrets at API startup (Identity A)
  • Map format ENV_VAR:vaultSecret
  • Does not overwrite already-set env (local .env wins)

PII guardrails (expandable)

  • SSN · credit card · account # · member id
  • Current agents: telemetry only (no expected PII)
  • Pattern registry designed for easy extension

Observability

LangSmith in the architecture

Cloud projects per env for SDBX/DEV/PROD · self-hosted Docker needs Enterprise license

Recommended for local testing

LangSmith Cloud (SaaS)

  • Create projects: edim-dde-sdbx / -dev / -prod
  • Set LANGCHAIN_TRACING_V2=true + API key + project
  • EDIM tags: agent_id, env, request_id
  • Works from laptop without Docker of LangSmith itself

Optional · Enterprise only

Self-hosted LangSmith (Docker)

  • Official Docker Compose exists for dev/test
  • Requires LangSmith Enterprise license key
  • Not open-source; not for free local spin-up
  • See platform/langsmith-setup.md § Local / Docker

Correlation & logging

  • request_id — from X-Request-Id or generated UUID; echoed on response; stdlib logs show [request_id=…]
  • EDIM_ENV — sdbx | dev | prod
  • agent_id — cluster_tuning / spark_rca / plugins
  • API failures: original stack logged once at the boundary (secrets/PII redacted); HTTP body stays short
