Identity, secrets & PII (R1)

Keep current auth model · Key Vault SDK · expandable PII patterns

Identity (unchanged model)

  • SQL (Apps): user OAuth via forwarded token
  • SQL (local): az login / DefaultAzureCredential
  • Foundry (local): DefaultAzureCredential
  • Foundry (PROD): SP from Key Vault → env

Role matrix (docs only in Phase 0)

  • invoke — call agent APIs
  • operate — view LangSmith, support
  • administer — register agents, rotate secrets
  • approve_tools — future HITL / MCP gates

“Docs only” means we define roles now; API does not yet enforce role claims. Identity paths above still apply.

Key Vault

  • SDK loads secrets at API startup
  • Maps vault names → env vars
  • Does not overwrite already-set env

PII guardrails (FinTech baseline)

  • SSN, credit card (PAN), account #, member id
  • Redact before logs / LangSmith payloads
  • Pattern list is expandable later
  • Current agents use telemetry (no expected PII)

R1 scope & non-goals

What Release 1 delivers vs what waits for later phases

In R1 / Phase 0

  • Three packages at 1.0.0
  • YAML schema contract + validation
  • cluster_tuning + spark_rca reference agents

  • MCP connectors (ADO / SNOW / JIRA)
  • Enterprise RAG / Azure AI Search
  • HITL review UI
  • Governance dashboard
  • Role enforcement beyond current identity
